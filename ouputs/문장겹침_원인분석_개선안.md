# 응답결과.hwpx 문장 겹침 — 원인 분석 및 개선안

작성: 2026-07-13. 대상 파일: `ouputs/응답결과.hwpx` (스텁 템플릿에 C안 fill 전량 재작성으로 생성한 산출물)

## 1. 증상

한컴오피스에서 열면 문장들이 서로 겹쳐 출력된다.

## 2. 파일 실측 결과

- 원본은 스텁 템플릿("AI 시대 행안부 행정문서 작성 가이드라인(안) 보고" + "가. 텍스트" + `<>` 6×4 표).
  `Preview/PrvText.txt`에 원본 내용이 그대로 남아 있어 생성 경로가 확인됨(fill → export).
- **모든 문단·표 셀에 원본 템플릿 시절의 `<hp:linesegarray>`(한컴 줄배치 캐시)가 그대로 남아 있다:**
  - 본문 문단 9개: vertpos 0 → 2560 → 4640 → … → 24898, 전부 lineseg **1개**(= 1줄 기준 배치)
  - 표 셀 문단 24개: 전부 lineseg 1개(vertpos 0, height 1000)
  - 표 크기: `sz height=7692 ABSOLUTE` — 스텁 `<>` 1줄 기준(행당 약 1282 HWPUNIT ≈ 4.5mm)
- 채워진 새 텍스트는 원본보다 훨씬 길다(셀 50자 이상, 본문 "가. 계획 수립 근거 및 목적 - 「감염병의 예방 및…" 등).
  실제 렌더링 시 2~5줄로 줄바꿈되지만, 캐시는 여전히 "1줄"이라고 말하고 있다.

## 3. 근본 원인

`app/core/hwpx/edits.py`의 `apply_edits`가 **hp:t 텍스트만 교체·삽입하고, 편집된 문단의
`linesegarray`를 제거·갱신하지 않는다.** 한컴오피스는 문서를 열 때 저장된 lineseg 줄배치를
재사용하므로, 옛 텍스트(1줄) 기준 좌표에 긴 새 텍스트가 들어가면 늘어난 줄들이 다음
문단/행 위에 겹쳐 그려진다.

교차 근거 — 의존 라이브러리 python-hwpx 자체가 동일 증상을 실측·문서화하고 있다
(`hwpx/body_patch.py:137`):

> 편집된 문단의 linesegarray(한컴 줄배치 캐시)를 함께 제거해야 한다 — 안 지우면
> 한컴이 옛 텍스트 기준 줄배치를 재사용해 긴 새 텍스트가 겹쳐 렌더된다
> (2026-07-07 AI중점학교 신청서 실측: 교체 문단만 줄겹침, lineseg 제거된 클론 문단은 정상)

python-hwpx의 모든 편집 모듈(`patch.py`, `table_patch.py`, `form_fill.py`, `body_patch.py`)이
"편집한 문단의 linesegarray 제거"를 표준 절차로 삼는다. linesegarray는 레이아웃 **캐시**
(선택 요소)라서 없으면 한컴이 열 때 재계산한다 — 제거가 곧 정상 렌더링이다.

기여 요인: C안(fill 전량 재작성)으로 텍스트 길이가 급증하면서 캐시 불일치가 극대화됐다.
기존 실양식 edit처럼 짧은 교체는 줄 수가 안 변해 증상이 드러나지 않았던 것.

추가 관찰(치명적이진 않음): `_ensure_t_elem`(빈 셀 채움, A1)은 오히려 "linesegarray **앞에**"
run을 삽입해 stale 캐시를 의도적으로 보존하고 있다.

## 4. 개선안

1. **(필수) apply_edits에서 편집된 노드의 소속 hp:p마다 linesegarray 제거**
   - `parse_section`이 이미 반환하는 `parent_map`(현재 apply_edits에서 미사용)으로
     각 편집 t_elem의 조상 hp:p를 찾아 `hp:linesegarray` 자식을 제거
   - `_ensure_t_elem`(빈 셀 삽입 경로)도 삽입 대상 p의 linesegarray 제거
   - **미편집 문단의 캐시는 보존** — 문서 전체 삭제는 불필요하고, 미편집 영역의
     초기 렌더 품질을 해칠 수 있음
2. **(권장) 회귀 테스트 추가**: 편집 문단은 linesegarray 부재, 미편집 문단은 보존,
   `validate_hwpx` 통과를 단언. 기존 194개 테스트 통과 유지.
3. (선택) `Preview/PrvText·PrvImage`가 원본 템플릿 것 그대로 재패키징됨 — 탐색기/미리보기에
   옛 내용이 보인다. PrvText는 새 텍스트 앞부분으로 재생성 가능. 최소한 `docs/limitations.md`에 명시.
4. (선택) lineseg 제거 후에도 표 안 겹침이 남으면 2차로 표 `sz height`/`cellSz` 조정 검토.
   한컴은 통상 셀 높이를 최소값으로 취급해 자동 확장하므로 우선순위 낮음 — 실측 후 판단.
5. 참고: 앱 HTML 미리보기의 `.page` 분할은 섹션 단위(lineseg 미사용, `html.py` 확인)라
   본 수정의 영향 없음.
